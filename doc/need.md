# 私人营养师系统 —— 需求分析文档

**版本**：v1.1（增加社交功能）  
**周期**：2周  
**小组**：4人  
**技术栈**：SpringBoot + Python FastAPI + Vue3 + MySQL  
**协作**：Gitee（开发分支 + 文档分支）

---

## 一、引言

### 1.1 编写目的
本文档旨在明确“私人营养师系统”的功能需求、非功能需求、约束条件和验收标准，作为项目开发、测试和验收的依据。

**读者对象**：
- 项目组成员（开发、测试）
- 指导老师（评审）
- 答辩评委（了解需求）

### 1.2 项目背景
专业营养师费用高、预约难，普通人难以获得个性化饮食指导。外卖和食堂时代，人们不清楚自己吃了多少、缺什么。减肥、增肌、控糖人群庞大，但缺乏可执行的日常建议。网上营养信息杂乱，缺乏权威、个性化的解读。

此外，独自记录饮食难以坚持，缺乏反馈和互动。用户希望看到别人的健康饮食，也希望自己的努力被看见。

### 1.3 项目目标
构建一个AI驱动、带社交互动的私人营养师系统，实现：
- **会看**：拍照识别食物，自动估算营养
- **会算**：每日营养摄入分析，缺口可视化
- **会建议**：基于权威膳食指南，给个性化建议
- **会生成**：根据目标、预算、忌口，生成菜谱和购物清单
- **会互动**：公开记录可被点赞、评论，形成健康饮食社区

### 1.4 术语定义
| 术语 | 说明 |
|------|------|
| MVP | 最小可行产品 |
| RAG | 检索增强生成 |
| LLM | 大语言模型 |
| JWT | JSON Web Token |
| BMR | 基础代谢率 |
| 分楼 | 评论支持回复，形成两层结构 |

- 《中国居民膳食指南（2022）》
- WHO营养建议
- SpringBoot官方文档
- FastAPI官方文档

## 二、总体描述

### 2.1 产品定位
不是“卡路里记账App”，而是有AI大脑、有社交互动的营养师社区——能识别、能分析、能建议、能生成，还能晒记录、被点赞、被评论。

### 2.2 用户画像

| 用户类型 | 核心需求 | 使用场景 |
|---------|---------|---------|
| 减脂人群 | 控制热量、保证营养 | 每餐拍照记录，看缺口，晒记录 |
| 增肌人群 | 保证蛋白质 | 记录+菜谱生成，看别人怎么吃 |
| 控糖/三高 | 避免禁忌食物 | 记录+建议 |
| 普通白领 | 吃得健康 | 拍照记录，周报总结，逛广场 |
| 社交型用户 | 被看见、被鼓励 | 公开记录，收点赞评论 |

### 2.3 运行环境
- **前端**：浏览器（Chrome/Edge）
- **后端**：JDK 17+、Python 3.10+
- **数据库**：MySQL 8.0
- **部署**：本地或云服务器

### 2.4 约束条件
- 周期：2周（实际开发约1周多）
- 人力：4人
- 技术：SpringBoot为主，AI用Python微服务
- 协作：Gitee分支管理
- AI：调用API，不训练模型

### 2.5 假设与依赖
- 假设用户有智能手机可拍照
- 依赖多模态LLM API可用
- 依赖膳食指南公开数据

### 3.2 用户模块

#### 3.2.1 注册
- **输入**：用户名、密码、身高、体重、年龄、性别、目标、忌口、过敏原
- **处理**：校验用户名唯一，密码加密，计算基础代谢
- **输出**：用户ID、Token
- **异常**：用户名已存在、密码太弱

#### 3.2.2 登录
- **输入**：用户名、密码
- **处理**：校验密码，生成JWT
- **输出**：Token、用户画像
- **异常**：用户名不存在、密码错误

#### 3.2.3 用户画像
- **输入**：身高、体重、年龄、性别、目标、忌口、过敏原
- **处理**：保存，计算基础代谢和目标摄入
- **输出**：更新后的画像
- **异常**：数据格式错误

#### 3.2.4 个人主页
- **输入**：用户ID
- **处理**：查询该用户的公开记录、点赞数、评论数
- **输出**：公开记录列表、统计信息
- **异常**：用户不存在
- **权限**：所有人可见（仅公开记录）

### 3.3 记录模块

#### 3.3.1 拍照录入
- **输入**：食物照片
- **处理**：上传图片 → 调用AI识别 → 返回营养数据 → 用户确认/修正 → 保存
- **输出**：记录ID、营养数据
- **异常**：图片格式错误、识别失败

#### 3.3.2 文字录入
- **输入**：食物描述（如“一碗牛肉面”）
- **处理**：调用AI识别 → 返回营养数据 → 用户确认 → 保存
- **输出**：记录ID、营养数据
- **异常**：描述不清

#### 3.3.3 手动修正
- **输入**：修正后的食物名、份量、营养数据
- **处理**：更新记录，标记is_corrected
- **输出**：更新后的记录
- **异常**：记录不存在

#### 3.3.4 记录管理
- **输入**：日期、餐次
- **处理**：查询、删除
- **输出**：记录列表
- **异常**：无记录

#### 3.3.5 公开/私密设置
- **输入**：记录ID、可见性（public/private）
- **处理**：更新记录的visibility字段
- **输出**：更新后的记录
- **异常**：记录不存在、非本人操作
- **规则**：
  - 默认私密
  - 可随时切换
  - 公开后出现在广场，所有人可见
  - 私密记录不可被点赞、评论

### 3.4 AI识别模块（核心）

#### 3.4.1 食物识别
- **输入**：图片Base64或文字描述
- **处理**：调用多模态LLM，识别食物、估算份量、营养
- **输出**：食物列表，含名称、份量、热量、蛋白质、脂肪、碳水、纤维、钠、置信度
- **异常**：识别失败、置信度过低

#### 3.4.2 营养估算
- **输入**：食物名称、份量
- **处理**：LLM估算或查食物库
- **输出**：营养数据
- **异常**：食物未知

#### 3.4.3 置信度返回
- **输入**：识别结果
- **处理**：LLM给出置信度
- **输出**：0-1的置信度
- **异常**：无

### 3.5 分析模块

#### 3.5.1 每日聚合
- **输入**：用户ID、日期
- **处理**：汇总当日所有记录的营养
- **输出**：总热量、蛋白质、脂肪、碳水、纤维、钠
- **异常**：无记录

#### 3.5.2 缺口分析
- **输入**：每日聚合、用户目标
- **处理**：计算缺口
- **输出**：缺口数据
- **异常**：目标未设置

#### 3.5.3 一周趋势
- **输入**：用户ID、周
- **处理**：汇总一周数据
- **输出**：每日数据、趋势
- **异常**：无数据

### 3.6 AI建议模块（核心）

#### 3.6.1 RAG检索
- **输入**：用户问题或缺口
- **处理**：向量检索膳食指南
- **输出**：相关段落
- **异常**：无相关

#### 3.6.2 建议生成
- **输入**：用户画像、当日摄入、缺口、检索内容
- **处理**：LLM生成建议
- **输出**：建议文本、依据
- **异常**：生成失败

#### 3.6.3 安全拦截
- **输入**：建议
- **处理**：规则检查（热量低于基础代谢、极端节食、违禁药物、过敏原冲突）
- **输出**：安全/不安全，原因
- **异常**：无

### 3.7 AI菜谱模块（核心）

#### 3.7.1 菜谱生成
- **输入**：目标、预算、食材、忌口
- **处理**：LLM生成一日三餐
- **输出**：早餐、午餐、晚餐、购物清单
- **异常**：生成失败

#### 3.7.2 购物清单
- **输入**：菜谱
- **处理**：汇总食材
- **输出**：购物清单
- **异常**：无

### 3.8 社交模块（新增）

#### 3.8.1 公开广场
- **输入**：分页参数、排序方式、餐次筛选
- **处理**：查询所有visibility=public的记录
- **输出**：公开记录列表，含用户信息、食物图、营养摘要、点赞数、评论数
- **异常**：无公开记录
- **权限**：所有人可见
- **排序**：按时间倒序（默认）或按点赞数
- **分页**：每页10条

#### 3.8.2 点赞
- **输入**：记录ID
- **处理**：
  - 校验记录是否公开
  - 校验是否已赞
  - 未赞则新增，已赞则取消
- **输出**：点赞数、是否已赞
- **异常**：记录不存在、记录私密、未登录
- **规则**：
  - 每人每条记录只能赞一次
  - 可取消点赞
  - 私密记录不可赞

#### 3.8.3 评论（分楼）
- **输入**：记录ID、评论内容、父评论ID（可选）
- **处理**：
  - 校验记录是否公开
  - 一级评论：parent_id为空
  - 二级回复：parent_id指向一级评论
  - 最多两层，不允许无限嵌套
- **输出**：评论ID、评论内容、用户信息、时间
- **异常**：记录不存在、记录私密、内容为空、父评论不存在
- **规则**：
  - 支持一级评论和二级回复
  - 回复时显示“回复 @某人”
  - 只能删自己的评论
  - 私密记录不可评

#### 3.8.4 评论展示
- **输入**：记录ID
- **处理**：查询该记录的所有评论，按楼层组织
- **输出**：
  - 一级评论列表（按时间倒序）
  - 每条一级评论下的回复列表（按时间正序）
- **异常**：无评论

#### 3.8.5 评论删除
- **输入**：评论ID
- **处理**：校验是否为本人，删除评论及其回复
- **输出**：删除结果
- **异常**：评论不存在、非本人

## 四、非功能需求

### 4.1 性能
- 页面响应 < 2秒
- AI识别 < 10秒
- 支持10人并发
- 广场分页查询 < 1秒

### 4.2 安全
- 密码加密存储
- JWT鉴权
- 危险建议拦截
- 免责声明
- 私密记录不可被他人访问
- 评论/点赞需登录

### 4.3 可用性
- 界面简洁，3步内完成记录
- 支持手动修正
- 错误提示友好
- 广场浏览流畅

### 4.4 可维护性
- 代码规范，注释清晰
- 接口文档完整
- 分支管理规范

### 4.5 可扩展性
- AI微服务独立，可替换模型
- 模块化设计，便于加功能
- 社交模块可扩展（关注、通知等）

## 十一、附录

### 11.1 基础代谢公式
- 男性：BMR = 10×体重 + 6.25×身高 - 5×年龄 + 5
- 女性：BMR = 10×体重 + 6.25×身高 - 5×年龄 - 161

### 11.2 目标摄入
- 减脂：BMR × 1.2 - 500
- 增肌：BMR × 1.5 + 300
- 维持：BMR × 1.3

### 11.3 危险建议规则
- 热量 < BMR
- 极端节食（< 800 kcal）
- 推荐违禁药物
- 与过敏原冲突

### 11.4 评论分楼规则
- 一级评论：parent_id为空
- 二级回复：parent_id指向一级评论
- 最多两层，不允许无限嵌套
- 回复时显示“回复 @某人”
- 删除一级评论时，其下回复一并删除

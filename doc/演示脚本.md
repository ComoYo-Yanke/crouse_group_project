## 二、演示流程

### 环节1：注册登录 + 画像（30秒）

**操作**：
1. 打开浏览器，访问 http://localhost:5173
2. 点击“注册”
3. 填写：用户名 `demo`，密码 `123456`
4. 填写画像：身高 175，体重 75，年龄 22，性别男，目标“减脂”
5. 点击注册

**讲解词**：
> “首先我们注册一个账号。用户画像包括身高、体重、目标等信息，系统会自动计算基础代谢和目标摄入。这是后续 AI 建议的基础。”

**预期结果**：
- 注册成功，自动登录
- 跳转到首页

**备用**：如果注册慢，直接用已登录账号。

---

### 环节2：拍照识别（1分钟）【核心】

**操作**：
1. 点击“记录一餐”
2. 选择“拍照上传”
3. 上传准备好的“牛肉面”图片
4. 等待 AI 识别（约 5-10 秒）
5. 展示识别结果：牛肉面，热量 450，蛋白质 20，脂肪 15，碳水 60，置信度 0.85
6. 点击“确认保存”
7. 再演示“文字录入”：输入“两个鸡蛋”，识别后保存

**讲解词**：
> “这是我们的核心功能——拍照识别。我们调用多模态大模型，识别食物并估算营养。可以看到，它返回了食物名称、份量、热量、蛋白质等，还有置信度。如果识别不准，用户可以手动修正，这是人机协同的设计。除了拍照，也支持文字录入。”

**预期结果**：
- 识别成功，返回营养数据
- 保存成功，首页记录更新

**备用**：如果 API 慢，展示提前录屏。

---

### 环节3：每日报告（30秒）

**操作**：
1. 点击“报告”
2. 展示今日摄入：热量 1200/1800，蛋白质 50/90，脂肪 40/60，碳水 150/200
3. 展示缺口：热量 -600，蛋白质 -40
4. 切换到“一周趋势”，展示折线图

**讲解词**：
> “记录后，系统自动聚合每日营养。这里可以看到今日摄入和目标对比，红色是缺口。用户能直观知道自己缺什么。一周趋势图展示每天的变化，帮助用户调整。”

**预期结果**：
- 报告正常显示
- 图表加载流畅

---

### 环节4：AI建议（1分钟）【核心】

**操作**：
1. 点击“AI建议”
2. 点击“下一餐吃什么”
3. 等待生成（约 5 秒）
4. 展示建议：“根据你的缺口，建议晚餐补充 40g 蛋白质。推荐：鸡胸肉 150g + 西兰花 200g + 糙米饭 100g。依据：《中国居民膳食指南》第X页……”
5. 展示“依据”来源

**讲解词**：
> “这是 AI 建议功能。它不是让大模型自由发挥，而是基于 RAG——先从《中国居民膳食指南》检索相关内容，再让模型基于检索结果生成建议。所以每条建议都有依据，避免胡说。同时我们做了安全拦截，如果建议热量低于基础代谢，会被拦截。”

**预期结果**：
- 建议合理，有依据
- 安全拦截正常

**备用**：如果生成慢，展示提前准备的截图。

---

### 环节5：菜谱生成（30秒）

**操作**：
1. 点击“生成菜谱”
2. 输入：目标“减脂”，预算 50 元，忌口“香菜”
3. 点击生成
4. 展示：早餐、午餐、晚餐 + 购物清单
5. 确认菜谱不含香菜

**讲解词**：
> “知道缺什么之后，用户可能还是不知道吃什么。菜谱生成根据目标、预算、忌口，生成一日三餐和购物清单。可以看到，忌口香菜被正确过滤了。”

**预期结果**：
- 菜谱合理
- 忌口生效

---

### 环节6：社交互动（1分钟）【亮点】

**操作**：
1. 回到首页，将刚才的记录设为“公开”
2. 点击“广场”
3. 展示公开记录列表（含其他用户记录）
4. 点击某条记录，点赞 → 点赞数 +1
5. 再次点击 → 取消点赞
6. 发表评论：“看起来很好吃！”
7. 回复某条评论：“谢谢！”
8. 展示分楼效果：“回复 @某某”
9. 点击用户头像 → 进入个人主页

**讲解词**：
> “记录不只是自己看。用户可以把记录设为公开，出现在广场。其他人可以点赞、评论。评论支持分楼，一级评论和二级回复，最多两层，避免无限嵌套。点击头像可以看个人主页。这样形成健康饮食社区，提高用户坚持动力。”

**预期结果**：
- 广场正常显示
- 点赞/取消正常
- 评论分楼正常
- 个人主页正常

**备用**：如果数据少，提前准备多条公开记录。

---

### 环节7：工程规范（30秒）

**操作**：
1. 打开 Gitee 仓库页面
2. 展示分支结构：main / develop / docs / feature-*
3. 展示提交记录：Conventional Commits
4. 展示 PR 记录
5. 展示 docs 目录：需求分析、接口文档、数据库设计、测试文档、分工文档

**讲解词**：
> “工程规范方面，我们采用 Gitee 分支管理，代码和文档分离。每人独立 feature 分支，完成后 PR review 合并。提交遵循 Conventional Commits。文档与开发同步，包括需求分析、接口文档、数据库设计、测试文档和分工文档。”

**预期结果**：
- Gitee 页面正常展示
- 分支、提交、PR、文档清晰

## 四、演示注意事项

### 4.1 操作注意
- 提前登录，避免现场输入慢
- 图片提前准备好，不要现场找
- 网络不稳时，及时切录屏
- 每步操作后停顿 1-2 秒，让评委看清

### 4.2 讲解注意
- 语速适中，吐字清晰
- 突出 AI 核心，不要只念界面
- 讲“为什么这么做”，不只是“做了什么”
- 遇到问题不慌，切备用方案

### 4.3 应急方案

| 问题 | 应对 |
|------|------|
| AI API 慢 | 切录屏 |
| 后端崩溃 | 切录屏 |
| 网络断开 | 切录屏 |
| 数据丢失 | 提前备份数据库 |
| 演示账号被锁 | 准备备用账号 |

## 六、演示后的答疑准备

| 可能问题 | 回答要点 |
|---------|---------|
| 识别不准怎么办？ | 人机协同，手动修正，置信度提示 |
| 建议不专业怎么办？ | RAG限定知识源，安全拦截 |
| 为什么用Python做AI？ | Python生态调LLM/向量库更顺 |
| 两周怎么做完？ | MVP原则，砍非核心，4人并行 |
| 社交会不会太重？ | 只做公开/点赞/评论，不做关注/私信 |
| 数据安全怎么保证？ | JWT鉴权，私密隔离，密码加密 |
| 和普通App区别？ | AI识别+RAG+菜谱+社交，不是记账 |
| 测试怎么做的？ | 36用例，AI效果测试，通过率≥90% |
